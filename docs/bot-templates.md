# 机器人命令模板

命令的「说什么」和「怎么算」是分开的：

- `app/bot/expr.py`：模板引擎，把占位符解析成节点树再求值；
- `app/bot/dataset.py`：数据层，提供设备、排行、总排行、电量四类数据集；
- `app/bot/commands.py`：**文案与命令表**，所有用户可见文字都在这里的模板字符串中；
- `app/bot/router.py`：只做准入判断、命令分发与异常兜底。

改措辞、加一条命令，只改 `commands.py`。引擎本身不用动。

## 1. 为什么不做成配置文件

主人 2026-11-01 明确拍板：文案改一次就不改了，不引入 `templates.yaml`、不做热加载、
不加看板编辑页。所以模板是**代码常量**，跟着 git 走，改动有测试兜底。

## 2. 占位符语法

| 写法 | 含义 | 例子 |
| --- | --- | --- |
| `{名称}` | 取变量，中文名自动映射到英文字段 | `{名称}` → 本机 Windows |
| `{device.name}` | 点号路径 | 同上 |
| `{排行[0].app}` | 下标路径 | 第一个应用 |
| `{时长\|时长}` | 套格式化器 | `3 分 20 秒` |
| `{占比\|百分比(0)}` | 格式化器带参数 | `67%` |
| `{若 有电量}…{否则}…{/若}` | 条件，可嵌套 | 有无电量两种文案 |
| `{>设备详情}` | 引用片段，共享作用域 | 一段可复用文案 |
| `{查询 设备 有使用=1分钟 行=设备行}` | 查询并逐行渲染 | 见下 |
| `{{` / `}}` | 字面量花括号 | `{设备}` |

变量取不到时输出空串并记一条 `WARNING`；片段名写错会**立刻报错**，不会静默少一段。

### 格式化器

| 名称 | 作用 | 参数 |
| --- | --- | --- |
| `时长` | 秒数 → `2 小时 5 分` | 无 |
| `相对` | 时间 → `12 秒前` | 无 |
| `时间` | 时间 → `2026-11-01 08:30` | 无 |
| `百分比` | 数字 → `66.7%` | 小数位，默认 1 |
| `数字` | 去掉多余小数 | 无 |
| `秒` | `1分钟` → `60` | 无 |
| `列表` | 列表/字典 → 顿号连接 | 无 |
| `截断` | 超长加省略号 | 最大长度，默认 16 |

空值不参与格式化，所以不会出现「0 秒」这种假数据。

## 3. 查询占位符

一条查询的骨架是 `{查询 <数据集> <键>=<值> …}`，键顺序无关，值里有空格时用双引号包住。

### 数据集

| 数据集 | 用途 | 必填 |
| --- | --- | --- |
| `设备` | 全部设备 | — |
| `排行` | 单台设备的应用排行 | `设备=` |
| `总排行` | 跨设备应用排行 | — |
| `电量` | 单台设备的电量采样 | `设备=` |
| `当前` | 遍历作用域里已有的列表 | `列表=` |

### 通用键

| 键 | 说明 |
| --- | --- |
| `最近=` / `窗口=` | 时间窗口，`1分钟` / `90秒` / `2小时` / `1天` |
| `小时=` | 按小时写窗口 |
| `行=` | 每行用哪个片段渲染 |
| `空=` | 结果为空时的文案 |
| `前=` | 最多几行，`0` 表示不限 |
| `按=` | 排序字段（可写中文名） |
| `正序` | 单独写这个词表示升序，默认降序 |
| `计数` | 返回行数 |
| `合计=` `最大=` `平均=` | 对指定字段聚合，返回标量 |

### 数据集专属键

- `设备`：`设备=`（ID 或前缀）、`平台=`、`角色=`、`在线=是/否`、`活跃=<窗口>`、`有使用=<窗口>`、`匹配=<关键词>`
- `排行`：`应用=`、`至少=<时长>`
- `总排行`：`设备数=<下限>`、`应用=`
- `电量`：`前=<条数>`
- `当前`：`列表=<变量名>`

`有使用=` 就是主人要的「最近 1 分钟有哪些设备在动」：它会先筛出窗口内有使用记录的设备，
再把每台设备在该窗口内的使用时长写进 `{使用时长}`。

## 4. 加一条新命令

在 `commands.py` 里加一个准备函数，再往 `COMMANDS` 里加一条 `Command`：

```python
def _my_scope(context: CommandContext) -> Mapping[str, Any]:
    """我的命令的数据准备喵。"""
    # 基础作用域已经带了命令名与参数喵
    scope = _base_scope(context)
    # 想查什么就调 dataset 里的函数喵
    scope["devices"] = dataset.list_device_rows(context.connection, context.now)
    return scope


Command(
    name="我的命令",
    aliases=("我的命令", "mycmd"),
    summary="一句话说明，会出现在 /帮助 里",
    usage="[可选参数]",
    template="{查询 当前 列表=设备列表 行=设备行}",
    handler=_my_scope,
),
```

注意：

1. `summary` 为空时这条命令**不会**出现在 `/帮助` 里；
2. 模板里中文变量靠 `expr.ALIASES` 映射，新增字段记得在别名表里登记；
3. 作用域里的键用英文，模板里写中文，两处各用顺手的写法。

## 5. 出错时会发生什么

| 情况 | 用户看到 | 日志 |
| --- | --- | --- |
| 命令名不在命令表里 | **什么都不回**（完全静默，2026-11-02 起） | `DEBUG`（router）+ `INFO`（runner） |
| 设备找不到 / 前缀歧义 | 明确的中文提示（由 `DeviceLookupError` 携带） | 无 |
| 参数个数/写法不对 | 用法提示或参数提示（还是照样回） | 无 |
| 模板语法错 | 「命令模板配置有误，已记录到服务端日志。」 | `ERROR` + 堆栈 |
| 查询参数写错 | 「命令查询条件有误，已记录到服务端日志。」 | `ERROR` + 堆栈 |
| 数据库异常 | 「服务端查询数据时出错，请稍后再试。」 | `ERROR` + 堆栈 |
| 变量名拼错 | 该处空串，其余正常 | 每个变量名一条 `WARNING` |

**除了「命令名根本不存在」这一种情况，其余一律不会静默不回复**，这是硬约束。
未知命令静默是为了避免在群里为每个手滑的命令名刷一段帮助；
一旦命令名对得上，说明用户确实在用这条命令，出错就必须说清楚。
判定点只有一处：`app/bot/router.py: is_silent_command`，
`build_reply` 对未知命令返回空串，runner 与看板「命令测试」共用同一个判定喵。

## 7. 图片输出

图片不是自己画的，而是**用无头浏览器截真实看板**：

```
/看看happy <全部/设备名> 排行榜 [时间窗口]        → 截「应用排行」页
/看看happy <全部/设备名> 时间轴 [日期] [起止时刻]  → 截「时间轴」页
```

为什么这么干：主人要的是「跟 webui 一模一样」的图。自己画等于把时间轴、
配色、排行的逻辑抄一遍，两边迟早跑偏；直接截页面就永远一致喵。

### 实现

| 文件 | 职责 |
| --- | --- |
| `app/bot/snapshot.py` | 拼 URL、调 node 脚本、读回 PNG、失败降级 |
| `scripts/shot_dashboard.js` | CDP 驱动 Edge/Chrome：注入口令、等渲染、按内容区裁剪 |

关键细节：

1. **只截内容区**：脚本默认裁 `main.page`，不会把顶部功能栏拍进去；
2. **参数靠查询串**：`?hours=2&scope=device&devices=<id>` 与 `?from=2026-11-01#/timeline`，
   前端 `readShotParams()` 读它，再同步按钮高亮，图里显示的档位才不会错；
3. **设备范围**：`devices=` 会一直传到 `/api/v1/rankings`，按设备口径时只留指定的那几台；
4. **口令注入**：先 `Page.navigate` 到目标页，等 `readyState=complete` 再写 `localStorage`，
   然后 `Page.reload` —— 不能改完 hash 就 reload，也不能再导航同一个 URL（同文档跳转不会重载）；
5. **失败降级**：缺 node、超时、脚本报错都只记 `WARNING` 并返回 `None`，
   命令自动退回文本回复，不会让机器人对一条合法命令沉默。

### 依赖

只需要系统里有 Edge 或 Chrome，以及 PATH 里的 `node`。没有额外 Python 依赖。

## 8. happy 系列：状态判定规则

这一族命令共用一个前提——**happy 绑定的是 `bot.happy_group` 指定的设备组**
（默认 `happy`，可在 WebUI「配置」页改；老配置没写这一节时按默认值走），
组内顺序就是优先级。数据准备在 `app/bot/happy.py`，命令只负责排版喵。

### 三档状态

`/happy在干嘛` 按「在用 > 挂机 > 不在」的顺序短路判定，多台设备同时满足时
一律取组内顺序靠前的那台：

| 状态 | 条件 |
| --- | --- |
| 正在使用 | 设备在线，且最近 3 分钟累计使用 ≥ 10 秒 |
| 挂机 | 设备在线，且空档（距最后一次使用）不超过 10 分钟 |
| 不在 | 其余情况，用最后一笔使用记录回答「最近一次上线」 |

这里的**空档**就是时间轴上那段 45° 斜纹：设备在线，但这一分钟没有任何使用记录。
它和客户端心跳里的 `afk` 标记**不是一回事**——被门控暂停计时（投屏窗口在前台、
RDP 未连接）时客户端报 `afk=false`，时间轴照样画斜纹，所以判定挂机不能看那个标记，
只能看空档本身有多长。`10 秒` 的下限是为了滤掉一次误采样就点亮状态的情况。

### 几个刻意的选择

1. **「有行为」看使用记录，不看心跳**：心跳只证明设备开着，使用记录才证明人在用；
   否则机器通宵开着会被判成「一直没离开」；
2. **挂机只看空档时长，不看 `afk` 标记**：门控暂停计时的设备 `afk=false` 但照样画斜纹，
   盯着标记会把这些设备永远排除在挂机之外；
3. **挂机档不报「当前应用已持续多久」**：那个数是 `now - current_app.since`，`since` 是
   「应用切到前台」的时刻，只要应用不换就一直涨，人走开多久它都在涨。挂机档报出来会
   和「可能在处理事情」自相矛盾，所以那里整段不显示；在用档才显示，因为那时 `since`
   是新鲜的；
4. **`current_app_json` 是 COALESCE 快照**：客户端某次上报不带 `current_app`（Windows 抓
   不到前台、Android 息屏）时会保留上一次的旧值，所以应用名改成取 `usage_samples` 最新
   一条，且应用名与快照对不上时连标题、时长一起丢掉（宁可少一行也不给错信息），
   时长另有 24 小时上限挡住陈旧快照；
5. **所有判定都以传入的 `now` 为准**：模块里不读真实时钟，测试才能把时间钉死；
6. **设备名支持前缀匹配**：`本机` 能匹配「本机 Windows」，`and-` 能匹配手机 ID。

## 9. 已知取舍

1. **没有任意代码执行**：只有白名单关键字，没有 `eval`，模板写不出死循环（深度上限 6 层）；
2. **截图比画图慢**：一次 3–10 秒（要起浏览器、等页面把数据取回来再画完），换来的是
   与看板零维护的对齐；
3. **每台设备查一次详情**：设备数是个位数时开销可忽略，将来设备多了需要改批量查询；
4. **秒级窗口单独聚合**：`总排行` 的纯秒级窗口走另一条 SQL，因为原有查询只支持按小时；
5. **时间轴自定义窗口**：看板一页固定 24 小时，窗口不是另画一块画布，而是把倍率反算成 `1440 / 窗口分钟数` 再滚动居中——30 分钟窗口就是 48 倍，10 分钟就是 144 倍，超过 8640 倍夹到上限；
6. **排行榜不支持指定历史日期**：看板排行页只认「最近 N 小时」，所以
   `/看看happy … 排行榜 <日期>` 这种写法没有实现，给了日期会提示时间窗口看不懂。
